# Casos de prueba — Pilares de Esperanza (IEEE 29119)

> Ámbito: app móvil B2C (React Native + Expo SDK 58) y portal web B2B (`AppWEB-claude`), sobre el proyecto Firebase `App-Dev-Pilares`.
> Estado: **diseño de pruebas**. Ningún caso fue ejecutado todavía; los resultados esperados se derivaron del código fuente vigente.
> Requerimientos de origen: [REQUERIMIENTOS.md](../1-diseno-y-requerimientos/REQUERIMIENTOS.md).

## 1. Estrategia de pruebas

### 1.1 Alcance

| En alcance | Fuera de alcance |
| --- | --- |
| Flujos de la app móvil (acceso, onboarding, turnos, perfil, soporte). | Calidad de imagen o validación biométrica real del DNI y el rostro (la captura es simulada en el código). |
| Portal web administrativo (login con rol, agenda, alta/estado/liberación, padrón y GPS). | Rendimiento bajo carga masiva y pruebas de estrés de Firebase. |
| Reglas de Firestore (RBAC) y consistencia App ↔ Web. | Seguridad de la infraestructura de Google Cloud y entrega de correos (SMTP de Firebase). |
| Integración con hardware nativo (cámara y GPS) y manejo de permisos. | Compatibilidad con navegadores o dispositivos no listados en el entorno de pruebas. |

### 1.3 Entorno y datos de prueba

- Proyecto Firebase de **pruebas** (o Emulator Suite), nunca el de producción.
- Un administrador (documento `administradores/{uid}` con `rol: "admin"`), dos o más pacientes con `pacientes/{uid}` y un usuario sin documento de administrador.
- Dispositivo Android/iOS físico con cámara y GPS; navegador de escritorio para el portal.
- Reglas de `firestore.rules` publicadas en el entorno de pruebas (o cargadas en el Emulator). Las pruebas automáticas de reglas necesitan **Java 11+** (el Emulator de Firestore) y no requieren credenciales: usan identidades simuladas.

### 1.4 Criterios de entrada y salida

- **Entrada:** build de la app y del portal compilando (`npm run build` en `AppWEB-claude`), variables `VITE_FIREBASE_*` configuradas, datos de prueba cargados.
- **Salida:** 100 % de los casos de prioridad Alta ejecutados y aprobados; sin defectos abiertos de severidad crítica; los defectos conocidos listados en el punto 4 documentados con decisión (corregir o aceptar).
